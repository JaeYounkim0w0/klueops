# 새 프로젝트에 적용하기

## 복사 범위

원본의 루트 `AGENTS.md`와 `docs/engineering/` 전체를 같은 상대 경로로 복사한다. 대소문자 혼선을 막기 위해 파일명은 `AGENTS.md` 하나만 사용한다. 대상 저장소에 이미 에이전트 지침이 있으면 덮어쓰지 말고 기존 규칙과 병합한다.

이 묶음은 설계·개발 기준이며 실행 가능한 starter는 아니다. 원본 소스, migration, Helm values, CI, 계정·Secret은 자동 복사 대상이 아니다.

## 초기 구성 순서

1. 제품 목적·주요 사용자 흐름·운영 환경·규모·데이터/보안 제약을 정한다.
2. [기술 스택](stack.md)에서 채택/대체/미사용 항목을 선택한다. 버전은 적용 시점의 호환성과 지원 정책을 확인해 manifest/lockfile에 고정한다.
3. `project-profile.md`를 아래 양식으로 교체한다. 원본 버전 표·경로·명령·제품 문서 링크는 지우고 새 저장소에서 존재하는 대상으로 작성한다.
4. Backend/Frontend 경로와 package, application 이름, 환경 변수 접두사, DB 이름, OpenAPI snapshot/client 경로를 정한다.
5. AI·Kubernetes·CLI·다국어 등 선택 모듈을 명시한다. 미사용 모듈은 의존성을 설치하지 않고 선택 기준 문서만 참고 자료로 둔다.
6. 필요한 코드/설정/스크립트를 실제로 구성하고 프로필 명령을 실행한다. 인증·단일 기능 API·UI·DB migration·오류 처리의 작은 수직 흐름을 먼저 검증한다.
7. CI에 타입·테스트·빌드·계약 drift·문서 검사를 연결한다. 구조/보안 규칙은 가능한 범위에서 자동 검사한다.
8. 프로젝트별 상세 문서와 ADR을 만들고 프로필에서 연결한다. `.codex/skills`가 없어도 공통 기준을 읽고 개발할 수 있어야 한다.

## 프로젝트 프로필 양식

아래를 새 `project-profile.md`의 출발점으로 사용한다. 미결정 값은 임의로 채우지 말고 담당 결정과 남은 작업을 적는다.

```markdown
# 프로젝트 프로필: <프로젝트명>

## 목적과 범위
- 사용자와 해결할 문제:
- 이번 범위 / 제외 범위:
- 예상 데이터 규모·동시성·응답 목표:

## 기술과 실제 경로
- Backend/Frontend 경로, package, 환경 변수 접두사:
- runtime/library 버전과 manifest/lockfile 근거:
- DB와 migration 경로:
- API snapshot / generated client 경로:
- 배포 방식과 관측 도구:

## 적용 모듈
- 인증/IdP 및 권한 범위:
- AI: 사용/미사용, provider 및 데이터 전송 경계
- Kubernetes/CLI: 사용/미사용
- 다국어: 사용/미사용, 지원 locale
- UI/CSS 정책: 공통 기준 채택 또는 대체 결정

## 실행과 검증
- 명령별 실행 위치·필수 도구·환경 변수:
- 실제 존재하는 개발/테스트/빌드/계약/문서 검증 명령:
- 성공 기준·실패 로그 위치·외부 환경 필요 여부:

## 상세 문서와 예외
- 제품/API/보안/운영/사용자 가이드의 실제 상대 링크:
- 기준 예외: 이유·적용 범위·검증 방법·재검토 조건
- ADR 위치:
```

## 이식 완료 확인

- [ ] `AGENTS.md`에서 모든 주제 문서에 접근할 수 있다.
- [ ] 프로필에 KlueOps/`io.product.aiops`/`AIOPS_`/원본 계정·주소가 의도 없이 남지 않았다.
- [ ] 상대 링크 대상이 새 저장소에 존재한다. 기존 제품 문서를 복사하지 않았다면 연결도 교체했다.
- [ ] 선언 버전과 lockfile/빌드 설정이 일치한다.
- [ ] 명령을 실제 실행했고 필수 도구·성공 조건이 기록되어 있다.
- [ ] 채택한 보안·아키텍처·UI 기준이 구현 및 검증에 반영됐다.
- [ ] 운영 검증과 미완료 항목을 구현 완료와 구분했다.

이후 공통 규칙 변경은 주제 문서에, 특정 프로젝트의 예외·명령·버전은 프로필에 기록한다. 검증하지 않은 원본 스크립트를 이름만 바꿔 완료 처리하지 않는다.
