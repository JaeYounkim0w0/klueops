# 재사용 개발 기준

이 묶음은 KlueOps에서 사용한 기술과 설계 원칙을 다른 프로젝트의 출발점으로 사용하기 위한 기준이다. 모든 기존 코드가 기준을 완전히 충족한다는 의미는 아니다.

## 문서 소유권

| 문서 | 담는 정보 | 새 프로젝트에서의 처리 |
| --- | --- | --- |
| [stack.md](stack.md) | 기술별 역할과 선택 기준 | 채택할 스택 확정 |
| [architecture.md](architecture.md) | 계층·데이터·API·비동기·코딩 원칙 | 도메인에 맞춰 적용 |
| [frontend.md](frontend.md) | UI 설계·스타일·상태·접근성 | UI 정책 확정 |
| [security-and-integrations.md](security-and-integrations.md) | 보안 공통 원칙과 AI/Kubernetes 선택 모듈 | 필요한 모듈만 활성화 |
| [quality.md](quality.md) | 검증·문서·완료 기준 | 실제 CI 명령 연결 |
| [project-profile.md](project-profile.md) | 현재 프로젝트의 버전·경로·명령·상세 문서 | 새 프로젝트 내용으로 교체 |
| [adoption.md](adoption.md) | 복사 범위와 초기 구성 절차 | 초기 설정 시 실행 |

`AGENTS.md`와 이 디렉터리 전체가 최소 복사 단위다. 공통 문서는 이 묶음 안에서만 서로 연결하며, 원본 저장소의 상세 문서 연결은 프로젝트 프로필에 모은다. 프로필을 교체하면 원본 프로젝트의 전체 `docs`나 `.codex/skills` 없이 사용할 수 있다. 문서만 복사해도 코드·스크립트·CI가 생성되는 것은 아니다.

## 현재 프로젝트 문서와의 관계

이 묶음은 프로젝트 간 재사용할 요약 기준이다. 현재 제품의 상세 계약은 프로필에서 연결하는 기존 architecture/API/security/development 문서가 소유한다. 세부 동작을 양쪽에 복제하지 않는다. 공통 정책을 바꿀 때는 해당 주제 문서와 영향을 받는 프로젝트 상세 문서를 함께 수정한다. 제품별 예외는 프로필에 이유·적용 범위·검증 방법을 기록한다.

문서에 나오는 **기본**은 이 기준을 채택한 프로젝트의 기본값, **선택**은 해당 기능을 채택했을 때만 적용하는 규칙이다. 현재 버전은 조사 시점의 기록이며 신규 프로젝트의 최신·권장 버전이라는 뜻이 아니다.
