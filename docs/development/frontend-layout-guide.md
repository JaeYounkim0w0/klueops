# 프론트엔드 UI 레이아웃 규칙

이 문서는 KlueOps UI의 큰 화면 구조와 배치 원칙을 정리한다. 개별 기능의 세부 디자인보다 공통 셸, 정보 계층, 화면 유형, 스크롤과 반응형 동작을 다룬다.

2026-09-23 기준 소스와 CSS를 확인했다. **현재 구현값**은 코드에서 확인한 값이고, **구성 원칙**은 새 화면에도 적용할 기준이다. 모든 기존 화면이 동일한 컴포넌트나 치수를 사용하는 것은 아니다. 브라우저 실측 보고서는 아니다.

## 1. 전체 화면 구조

인증된 업무 화면은 공통 셸 안에서 본문만 교체한다.

```text
┌──────────────────┬─────────────────────────────────────────────┐
│ 사이드바         │ 상단 컨텍스트 바                            │
│                  │ Tenant / Workspace       전체 검색 / 알림   │
│ 브랜드           ├─────────────────────────────────────────────┤
│ 전체 검색        │ 공통 운영 경고 / 화면 로딩 실패 안내        │
│                  │                                             │
│ 업무별 메뉴 그룹 │ 페이지 제목 · 설명              대표 액션   │
│ · 운영 현황      │                                             │
│ · 인프라         │ 요약 / 탭 / 필터                            │
│ · 애플리케이션   │                                             │
│ · AI / 관리      │ 업무 본문: 목록 · 상세 · 작업 영역          │
│                  │                                             │
│                  │ ┌─────────────────────────────────────────┐ │
│ 사용자 / 로그아웃│ │ 전역 Job Dock: 작업이 있을 때 표시       │ │
└──────────────────┴─┴─────────────────────────────────────────┴─┘
```

- 사이드바는 **어느 업무로 이동할지**, 상단 바는 **어느 범위에서 작업할지**, 본문은 **현재 무엇을 확인하고 실행할지**를 담당한다.
- 전역 검색·알림·세션 경고·Job Dock은 개별 페이지에서 중복 생성하지 않는다.
- `route.meta.public === true`인 공개 화면은 셸 없이 `RouterView`만 렌더링한다. 로그인 화면이 대표적인 별도 레이아웃이다.
- 공통 운영 경고와 route 오류는 페이지보다 앞에 배치한다. 페이지 내부 오류는 관련 작업 가까이에 표시한다.

## 2. 사이드바와 상단 바

### 사이드바

- 브랜드 → 검색 → 업무별 메뉴 그룹 → 사용자 정보 순서를 유지한다.
- 메뉴는 기술 객체를 무작정 나열하지 않고 운영 목적별로 묶는다. 현재 메뉴와 활성 상태를 명확히 구분한다.
- 메뉴 노출은 사용자 capability와 navigation 권한에 따른다.
- 메뉴가 길어지면 중앙 navigation만 세로 스크롤한다. 브랜드와 사용자 영역은 별도로 유지한다.
- 데스크톱은 `sticky` 사이드바이며 모바일에서는 왼쪽에서 열리는 고정 서랍으로 전환한다.

### 상단 컨텍스트 바

- Tenant/Workspace 선택을 왼쪽, 검색·알림 등 전역 도구를 오른쪽에 배치한다.
- 페이지별 생성·갱신 버튼은 페이지 헤더에 둔다. 전역 도구와 섞지 않는다.
- 상단 바는 스크롤 시 유지되는 `sticky` 영역이다. 작은 화면에서는 컨텍스트 선택 줄을 아래로 분리한다.

## 3. 본문과 페이지 헤더

일반 화면은 `.content` 안에 `.page`를 두고 다음 정보 순서로 구성한다. 필요 없는 요약이나 필터를 형식적으로 추가하지 않는다.

```text
페이지 헤더: 제목 + 한 줄 설명 | 대표 액션
페이지 상태: 오류 / 진행 / 결과 안내
선택 영역: 핵심 요약 / 목적별 탭 / 검색·필터
주요 본문: 목록 또는 상세·작업 영역
보조 정보: 이력 / 근거 / 펼쳐 보는 전문가 정보
```

- 제목은 현재 업무나 대상을 설명한다. 상세 화면은 상위 목록으로 돌아가는 경로를 제공한다.
- 데스크톱 페이지 헤더는 제목·설명을 왼쪽, 액션을 오른쪽에 둔다. 버튼이 많으면 줄바꿈한다.
- primary 스타일은 대표 행동에 사용하고 보조 행동과 위험 행동을 시각적으로 구분한다.
- 공통 본문 폭을 따르고 화면마다 별도 좌우 여백이나 최대 폭을 반복 정의하지 않는다.
- `min-width: 0`, `minmax(0, 1fr)`를 활용해 긴 데이터가 전체 페이지 폭을 늘리지 않게 한다.

## 4. 화면 유형별 구성

| 화면 유형 | 큰 배치 | 핵심 원칙 |
| --- | --- | --- |
| 대시보드 | 요약 지표 → 우선 대응 → 대상별 상태·추세 | 지금 확인할 문제와 다음 행동을 먼저 보여준다 |
| 목록 | 헤더 → 검색·필터 → 표/카드 → 페이지 이동 | 행 액션은 Operations/kebab 메뉴로 묶는다 |
| 상세 | 대상 식별·상태 → 요약/탭 → 선택한 정보 | 모든 정보를 한 번에 펼치지 않고 목적별로 나눈다 |
| 분석 | 요약·신뢰도·수집 한계 → 근거·권장 검증 → 상세 | 원문 JSON·로그보다 해석과 안전한 다음 행동을 먼저 제시한다 |
| 작업 공간 | 대상/설정 선택 영역 + 편집·실행·결과 영역 | 콘솔·채팅·Values 편집 등 작업 성격에 맞는 분할을 사용한다 |
| 입력·확인 | modal/drawer 또는 단계형 독립 화면 | 짧은 작업은 현재 맥락을 유지하고 긴 workflow는 단계와 복귀 경로를 제공한다 |

- 단순 화면은 1열을 기본으로 한다. 선택 영역과 결과 영역을 함께 봐야 할 때 2열 이상으로 나눈다.
- Cluster 상세처럼 보조 탐색과 본문을 나누는 구조도 있으므로 모든 상세 화면을 같은 카드 그리드로 강제하지 않는다.
- 복합 업무는 탭과 filter를 사용하며 상태를 URL에 보존해 deep-link와 새로고침을 지원한다.
- 카드와 표는 정보 성격에 따라 고른다. 비교·정렬은 표, 대상 요약과 진입은 카드에 적합하다.

## 5. 패널·스크롤·겹침

- 밝은 본문 배경 위에 흰색 surface, 공통 border/radius/shadow로 정보 묶음을 구분한다. 모든 문장을 개별 카드로 감싸지 않는다.
- 일반 본문은 문서의 세로 흐름을 따른다. 고정 높이와 내부 스크롤은 표·로그·터미널·modal처럼 필요한 영역에 한정한다.
- 넓은 표는 `.table-panel` 안에서 가로 스크롤한다. 페이지 전체의 가로 스크롤로 해결하지 않는다.
- 좁은 팝업의 비교 표는 `.table-panel--compact`처럼 열 고정과 줄바꿈을 지원하는 변형을 사용한다.
- 긴 로그·코드·YAML은 전용 viewer에서 크기와 스크롤을 제한하고 상세 내용은 접거나 분리한다.
- 행 메뉴는 스크롤 컨테이너 밖의 overlay layer에 표시해 clipping을 피한다.
- modal은 viewport 기준 backdrop 위에 배치한다. 제목·닫기·확인 영역에 접근할 수 있도록 높이와 내부 스크롤을 설계한다.
- layer를 바꿀 때 본문 → 고정 도구 → 탐색/상단 바 → modal 관계를 확인한다. `z-index`만 무조건 키우지 않고 stacking context도 확인한다.

현재 대표 layer 값은 Job Dock `30`, 상단 바 `70`, 모바일 backdrop `75`, 사이드바 `80`, 공통 modal backdrop `1000`이다. 다른 전용 overlay에는 별도 값이 있으므로 이를 전체 제품의 완전한 layer 목록으로 보지 않는다.

## 6. 전역 Job Dock

- 장시간 작업은 페이지를 이동해도 추적할 수 있도록 셸의 하단 고정 Dock에 표시한다.
- 작업이 있을 때 표시하고 접기/펼치기를 지원한다. 진행 상태를 페이지 local state에만 보관하지 않는다.
- Dock은 본문을 덮을 수 있으므로 `.content`의 하단 여백을 확보한다. 새 화면에서 이 여백을 제거하지 않는다.
- 데스크톱은 사이드바 오른쪽 영역, 모바일은 화면 좌우 여백 안에 배치한다.

## 7. 현재 공통 치수와 반응형 기준

아래는 공통 셸 기준이다. 기능별 CSS에는 추가 breakpoint와 전용 치수가 있다.

| 항목 | 현재 구현값 |
| --- | --- |
| 데스크톱 셸 | `260px minmax(0, 1fr)`, 최소 높이 `100vh` |
| 사이드바 | 높이 `100vh`, 메뉴 영역 내부 스크롤 |
| 상단 바 | 최소 높이 `68px`, padding `8px 30px` |
| 본문 | padding `18px 30px 132px` |
| 일반 페이지·공통 배너 | 최대 폭 `1680px`, 가로 중앙 정렬 |
| 페이지 section 간격 | `.page` 기본 gap `22px` |
| 페이지 제목 | `clamp(26px, 2.4vw, 34px)` |
| 공통 지표 grid | 기본 3열, gap `16px`; 800px 이하 1열 |
| 기본 HTML table | 최소 폭 `720px`; compact/기능별 규칙은 별도 |
| 공통 modal panel | 폭 `min(860px, 100%)`, 최대 높이 `min(860px, calc(100vh - 48px))` |
| 시각 토큰 | radius `8/12/18px`, 밝은 surface + 어두운 navigation |

| viewport | 공통 동작 |
| --- | --- |
| 1050px 이하 | 상단 검색의 텍스트·단축키 숨김, 범위 선택 label 최소 폭 축소 |
| 800px 이하 | 셸 1열, 사이드바 서랍화, 메뉴 toggle/backdrop 표시, 페이지 헤더 세로 배치 |
| 800px 이하 | 상단 바 최소 높이 `62px`, 본문 padding `16px 18px 146px`, Dock 좌우/하단 `12px` |
| 620px 이하 | 상단 바 줄바꿈, Tenant/Workspace 선택을 전체 폭의 다음 줄로 이동, 본문 좌우 `14px` |

모바일 사이드바 폭은 `min(280px, calc(100vw - 44px))`, 높이는 `100dvh`다. 경로 이동과 backdrop 클릭으로 메뉴를 닫는다. `body` 최소 폭은 `320px`이지만 이 선언만으로 모든 화면의 모바일 검증 완료를 의미하지 않는다.

## 8. CSS 소유권과 적용 순서

| 파일 | 소유하는 규칙 |
| --- | --- |
| `base.css` | 문서 기본값·색상·글꼴·radius 등 디자인 토큰 |
| `form-controls.css` | 공통 입력·form·surface primitive |
| `main.css` | 공통 page·표·modal·Job Dock 및 기존 교차 기능 규칙 |
| `product-shell.css` | 사이드바·상단 바·본문 폭·공통 셸 반응형 |
| `components/*.css`, `kubernetes-console.css` | 기능 고유의 분할·상태·상호작용 |

`main.ts`는 `product-shell.css`를 마지막에 import한다. `main.css`의 과거 셸 규칙만 보고 현재 레이아웃을 판단하지 말고 selector 우선순위·media query·최종 import 순서를 함께 확인한다.

Vue SFC 내부 style과 정적 inline style은 사용하지 않는다. 공통 배치를 먼저 재사용하고 기능별 CSS에는 해당 기능만의 차이만 둔다. 상세 구현 정책은 [Frontend Style Guide](frontend-style-guide.md)를 따른다.

## 9. 새 화면 검토 항목

- [ ] 공통 셸을 재사용하고 페이지가 전역 탐색/컨텍스트 바를 중복 생성하지 않는가?
- [ ] 제목·설명·대표 액션 → 요약/필터 → 본문 순서가 분명한가?
- [ ] loading·empty·error·success가 본문 구조 안에서 자연스럽게 표시되는가?
- [ ] 2열 이상인 경우 좁은 화면에서 읽는 순서와 작업 흐름을 유지하는가?
- [ ] 긴 이름·번역문·표·로그가 페이지 전체 폭을 늘리지 않는가?
- [ ] modal·행 메뉴가 상단 바나 스크롤 영역에 가려지지 않는가?
- [ ] Job Dock이 본문 마지막 행과 주요 액션을 가리지 않는가?
- [ ] 키보드 조작·focus·닫기/복귀 경로와 작은 화면을 확인했는가?

새 프로젝트에 적용할 때는 셸의 역할 분리와 정보 순서를 가져가고, 위 치수·breakpoint·메뉴 분류는 제품에 맞춰 결정한다.
